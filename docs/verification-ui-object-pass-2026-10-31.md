# Локальная UI-приёмка объекта — 2026-10-31

## Границы

Локальный объект `861c68b6-f458-46c9-bac4-a23a9b65ba92` («Приёмка графика · 29 октября»), существующая сессия директора. UI-only: новые DTO, ACL, миграции, расчёты и денежные операции не добавлялись. Production, сервер, commit и push не затрагивались. Существующие незакоммиченные изменения R1/R2/R3/R5 сохранены.

Референсы: [структура карточки Attio](https://attio.com/help/reference/attio-101/attios-data-model/understanding-records), [лента Greenhouse](https://support.greenhouse.io/hc/en-us/articles/360037386272-Candidate-activity-feed), существующие история заказов/контрагентов и скрепка CRM. Приоритет — STYLE_SOURCES, UI_ARCHITECTURE и COMPONENT_CONTRACTS.

## Реализовано

- Full-width просмотр сведений, штатных позиций и смен; bounded-формы сохранены. Даты предпросмотра ограничены по ширине.
- Посещаемость вынесена перед фото/отчётом на полную ширину; часы, ставка, сумма и основание адаптируются без переполнения. Предупреждения смен объединены без удаления сообщений.
- Две колонки прибытие/отчёт на широком экране, одна на узком; карточки не растягиваются по высоте соседней. Общая скрепка для прибытия и отчёта.
- Опциональный компактный AttachmentPreviewList: четыре превью по 108px, раскрытие всех вложений, имена фотографий только в доступных подписях/просмотре, скачивание иконкой; документы сохраняют название. Другие потребители без `compact` не меняют геометрию.
- Общий ActivityTimeline для ленты объекта, аудита объекта и истории заказа; прежние доменные форматтеры сохранены. Московские даты/время, автор, подробности, комментарии и файлы, без клиентского слияния разных источников. Фильтры ленты явно работают только по загруженным событиям.
- Сезонность выключена: базовый профиль и раскрываемые сохранённые настройки. Включена: границы и ближайшее переключение. Единица суммы соответствует типу оплаты, ноль не заменяется отсутствием значения. Базовые ставки отделены от контуров позиции; текущий ручной legacy-сезон учитывается. Контуры перечитываются при переходе обратно в #planning, с защитой от устаревшего ответа.

## Реальные браузерные сценарии

- Overview, Today, Team, Planning на 390/768/1280/1600 px: фактический innerWidth соответствует запросу; document.scrollWidth не превышает viewport; активные поля/кнопки не выходят вправо. Встроенная горизонтальная навигация остаётся прокручиваемой.
- На 390 px открыты поля особой ставки; сумма/основание доступны без горизонтального переполнения; исходное значение возвращено без сохранения.
- Галерея отчёта: 4 → 10 → 4; дождались загрузки последней фотографии перед подсчётом. В DOM и на скриншоте превью имеют высоту 108px. Прежние имена не занимают место под снимком.
- Удаление фотографии отмечено только локально: появилась кнопка «Вернуть» и действие исправления; затем «Сбросить несохранённые изменения» восстановило состояние. Мутация исправления не отправлялась.
- Меню фото прибытия показывает фото/галерею, не произвольный файл; Escape закрывает меню.
- Бюджет: введён 0 в черновик, Escape закрыл окно и вернул фокус кнопке; исходный «Не задан» сохранён. Сезонность включена только в черновике: ежегодные даты появились, отмена сохранила прежнее состояние.
- Предпросмотр графика вернул предупреждения/покрытие/пустой список ожидаемых смен; не создаёт факты/начисления.
- Поиск несуществующего события и фильтр комментариев дали 0 из 1; сброс вернул событие отчёта и вложения.
- Оригинал qa-photo-04.jpg открыт через штатный viewer, скачивание оригинала выполнено через браузер в Downloads. Новый file access path не добавлялся.

Во время приёмки отчёт был обновлён другой сессией: API позднее вернул 9 фотографий и автора Учредитель вместо первоначальных 10 и директора. Этот проход не отправлял сохранение/исправление отчёта и не откатывал эти изменения. Результат 4→10→4 относится к моменту проверки.

## Что не подтверждено

- Настоящий браузерный zoom 200%: сочетания клавиш не изменили innerWidth/devicePixelRatio/scale. Проверка 640px не выдаётся за zoom 200%.
- Реальные iPhone/Android, камера, системная клавиатура, VoiceOver/NVDA и полный кроссбраузерный набор.
- Полная ручная ролевая матрица, новые загрузки каждого типа документа и сетевые сбои каждого компонента. ACL/конфликты/повторы покрыты перечисленными integration/unit tests, но это не заменяет ручную приёмку всех ролей.
- Не заявляется полная визуальная приёмка всей CRM или завершение R0/R5. Работа ограничена согласованным объектным проходом и реальными потребителями общих компонентов.
