# Общие фотографии и быстрый доступ — локальная проверка 2026-10-31

## Граница изменения

Локальный frontend-проход. Production, сервер, схема и API не менялись в этом проходе. Существующие незакоммиченные изменения других блоков сохранены. Коммит/push/выкладка не выполнялись.

Рабочая группа: Luna/medium — карта потребителей и миграция; Luna/medium — общие превью, меню и просмотрщик; Sol 6.1/medium — независимое ограниченное ревью. Основной чат исправлял быстрый доступ, интегрировал изменения и проверял браузер. Агентам не разрешалось создавать дополнительных агентов.

## Что изменено

- `AttachmentPreviewList`: компактный вариант теперь по умолчанию для всех существующих потребителей. Первые четыре вложения, явное раскрытие остальных; фото без видимых имён, документы с названиями. Доступные имена и прямые ссылки сохранены.
- Обычный клик по фото открывает общий `FileViewer` поверх страницы. Модификаторы/открытие в новой вкладке сохраняют прежнюю ссылку `/files/:id/view`; эта страница использует тот же просмотрщик.
- Правый клик, Shift+F10 и кнопка `⋯` открывают одинаковое меню. Скачивание и доменные действия не перекрывают фотографию большими кнопками. `getFileActions` передаёт разрешённые действия; shared-компонент не определяет права и не удаляет файлы.
- Меню использует верхний слой браузера, ограничение доступной области и открытие вверх при нехватке места; закрывается при внешней прокрутке/resize. Исправлен End; Escape не закрывает родительский Drawer.
- Просмотрщик: существующие иконки скачивания/поиска, иконки вписывания и 1:1 в общей семье; оригинал для 1:1; лупа по курсору с учётом фактических размеров, краёв и пустых полей. Лупа только для точного указателя; на узком экране доступен 1:1 с прокруткой. Браузерный pinch-zoom не блокируется. Отдельного жестового pinch-контроллера масштаба фотографии не добавлено.
- Ошибки чтения имеют повтор безопасной загрузки, галерея сохраняет навигацию при ошибке отдельного файла; bounded polling не обещает автообновление после ошибки.
- Причина сбоя быстрого доступа: React передавал события close/cancel вложенного Dialog в родительский Drawer. Общая оболочка теперь обрабатывает только собственные события.
- Отчёт: помеченная фотография приглушена и подписана; видны количество добавлений/удалений, отмена и отдельное применение. Неизменённый отправленный отчёт не показывает лишнее «Сохранить черновик». Изменение текста и исправление вложений не отправляются одновременно.
- Быстрый доступ предупреждает о потере несохранённого текста отчёта, вложений и комментария при закрытии/ссылке из панели, а reload использует beforeunload. Полная защита браузерных Back/Forward и всех других редакторов не заявляется.
- Поле оперативного комментария блокируется на время его сохранения: успешный ответ не может стереть текст, дописанный во время запроса.
- ТЗ заказа: дублирующий список имён/кнопок удаления заменён действием меню с прежним подтверждением и прежним canExecute.
- Фото разового заказа: удаление всей записи остаётся отдельным меню записи с числом вложений, не выдаётся за удаление одного файла. Существующие причина/восстановление сохранены.
- Сняты старые обёртки превью в комментариях/расходниках объекта; удалены доказанно неиспользуемые стили `savedPhotosViewport` и `attachment-download-link`. Чатовые realtime/scroll/upload-контроллеры не переписывались.

### Живой браузер, роль Директор

- Реестр → быстрый доступ тестового объекта → меню фото → пометка удаления → причина → подтверждение → отмена. Родительская панель остаётся открытой; сохранённый отчёт не изменён.
- Закрытие с выбранным удалением вызывает предупреждение; отмена сохраняет выбор, сброс возвращает исходное локальное состояние.
- Раскрытие всех девяти вложений и сворачивание обратно.
- Правый клик; End переводит фокус на последний доступный пункт; Escape закрывает только меню.
- Фото открывается поверх Drawer; переход 1/9 → 2/9; Escape возвращает к объекту.
- На свежей странице стрелка в 1:1 сохраняет 1/9, в режиме вписывания переключает на 2/9. Клавиатурные обработчики ограничены просмотрщиком, не документом.
- 1:1 использует authenticated `/content`, а не производное превью. Лупа отображается по курсору.
- Прямая страница файла работает; скачивание оригинала реально сохранило `qa-photo-04 (1).jpg` в Downloads. Существующая копия не перезаписана.
- Ширины 390 и 1280 px подтверждены по фактическому innerWidth; на 390 px document scrollWidth также 390. Это проверка узкого окна, не реального сенсорного устройства и не zoom 200%.
- Для прямого просмотрщика дополнительно подтверждена геометрия 768/1600 px без document overflow. Скриншоты этих двух overrides не используются как визуальная evidence из-за несоответствия снимка фактическому viewport.

## Что не считать проверенным

- Полная ручная ролевая/маршрутная матрица CRM, все чаты, задачи, финансовые и складские сценарии после общего изменения.
- Настоящий browser zoom 200%, реальные touch/pinch, VoiceOver и остальные браузеры; фактический контраст всех состояний.
- Ручная финальная отправка удаления существующего фото: браузерная проверка остановлена на подтверждении и отменена. Сохранность данных/аудит/доставка проверены изолированными API-тестами, а не удалением пользовательских материалов.
- Ручная имитация медленной сети, polling failure, ошибок генерации PDF/text/unsupported и конфликта 409 в этом проходе. Их состояния сохранены в коде, часть конфликтов покрыта тестами.
- Прикрепления Employee/Candidate не выдумывались: общая миграция распространяется на существующие attachment-потребители, не на аватары и не на новые кадровые функции.

R0 остаётся открытым. Этот проход закрывает перечисленные локальные исправления, а не всю CRM.
