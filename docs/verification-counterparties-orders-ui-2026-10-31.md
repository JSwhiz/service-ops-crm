# Контрагенты и разовые заказы: локальный UI-проход

Дата начала: 2026-10-31. Источник объёма: `docs/product/current-roadmap.md`, UI-0–UI-6. F1 выбран заказчиком. Этот файл содержит результаты именно текущего прохода, а не переносит успешные статусы предыдущих релизов.

## Ограничения и безопасность

- Только локальная CRM. Production, удалённый сервер, commit/push/deploy не выполнялись.
- Исходный checkout содержал большой незакоммиченный пакет; изменения сохранены, reset/checkout/очистка не выполнялись.
- Luna A (`gpt-6-luna`, medium) — frontend, Luna B (`gpt-6-luna`, medium) — дополнительные серверные фильтры. Основной чат — координация, браузерная проверка, документирование.
- Браузер: текущая сессия директора. Несохранённый тестовый ввод контрагента отменён без записи. Финансовые поля проверяются без проведения реальных поступлений; денежные сценарии — в изолированных интеграционных схемах.

Во время реализации браузер находил промежуточные дефекты: отсутствующий импорт Button, полноширинную кнопку завершения в сводке, неверную подпись состояния этапа, нативные date-input и несвязанные объекты в фильтре. Они переданы исполнителям; окончательное закрытие требует повторной проверки стабильного результата. Кратковременная ошибка запросов при обновлении локального API не является успешной проверкой сценария ошибки.

## Выполненные команды

```sh
pnpm --filter backend test:integration -- test/one-time-order-completion.integration.test.ts test/one-time-order-completion-payments.integration.test.ts test/one-time-order-completion-access.integration.test.ts test/one-time-order-payment-corrections.integration.test.ts test/legacy-completion-current-state.integration.test.ts
```

Результат: 5/5, без пропусков. Тестовые схемы изолированы; основной локальный набор не использован для денежных операций.

Дополнительно выполнены frontend typecheck (PASS) и 16 unit-проверок общих меню, геометрии просмотра файлов, ссылок и черновиков исправления отчёта (PASS). Это промежуточная проверка; после последних правок команды должны быть повторены.

Живая проверка F1: ввод 12 000 + 1 000 ₽ показывает несохранённые 13 000 ₽; переход «Работы → Финансы» сохраняет обе строки; «Отмена» требует подтверждение и очищает форму без записи. Проверены раскрытие фото, общая скрепка и Escape без загрузки файла. На ширине 390 px проверены геометрия и читаемость F1, `scrollWidth=innerWidth=390`. Первый некорректно масштабированный снимок отвергнут; повторный просмотр показал нормальный масштаб. Ярлык ширины не является доказательством физического touch-устройства.

## Независимое ревью

Terra (`gpt-6.1-terra`, high) выполнила один read-only проход, использовала актуальные web-interface guidelines. Найдены четыре P2, переданы на исправление:

1. Новые фильтры даты контрагента считали UTC-дни, таблица показывала локальную дату. Привести новый scoped-фильтр и отображение к Москве, добавить граничные тесты; legacy глобальные фильтры склада не менять молча.
2. При ошибке фильтра сохранялись старые строки под новым выбором. Явно очистить/пометить устаревшие результаты и дать повтор.
3. Защита черновика заказа покрывала вкладки, но не уход со страницы/перезагрузку. Добавить соответствующую защиту, не заявлять browser Back проверенным без фактического сценария.
4. Успех завершения смешивался с ошибкой последующего refetch. Отделить успешную мутацию от предупреждения об обновлении, не повторять подтверждённую операцию.

Backend scope и фильтрация до count/pagination по результатам ревью сохранены. Ревью не заменяет браузерную приёмку; статусы исправлений ниже ещё требуют подтверждения.

## Финальная матрица — заполнить после стабилизации

### Локальная инфраструктура: подтверждённый блокер 2026-10-31

Повторные остановки — не только завершение браузерной сессии: поток Docker events зафиксировал `oom → die → start` для frontend и backend. В контрольном снимке Docker доступно 7,65 GiB, индивидуальных лимитов памяти у CRM нет; параллельно запущены контейнеры других проектов, в том числе CVAT. Пользователь подтвердил, что вручную ничего не перезапускает. Опрос `/login` и `/api/v1/health` возвращал HTTP 200 между падениями, поэтому такой ответ не доказывает стабильность.

После отдельного согласия пользователя временно остановлены все 18 контейнеров с проверенной меткой compose-проекта `cvat`, включая принадлежащий ему `traefik`. Контейнеры, образы и тома не удалялись. Другие проекты и настройки памяти Docker не менялись. Потребление оставшихся контейнеров — около 3,3 GiB из доступных 7,65 GiB. В повторном наблюдении новых OOM/остановок нет, счётчики рестартов frontend=8/backend=65 не увеличивались, оба healthcheck healthy; `/login` и `/api/v1/health` HTTP 200. Это ограниченное наблюдение, не гарантия отсутствия будущих сбоев.

Живая сессия директора в существующей вкладке работает. Повторно проверены загрузка карточки контрагента, переход из истории к редактированию и отмена без записи. После reload появился новый общий блок фильтров истории: выбор «Контрагент создан» уменьшил 18 событий до 1, счётчик/пагинация соответствуют результату; сброс выполнен.

После освобождения памяти команды выполнены последовательно:

- `pnpm --filter backend test:integration -- test/audit-history-filters.integration.test.ts` — 2/2 PASS в одной изолированной схеме. По обоим типам сущностей покрыты история больше 100 событий, фильтры до пагинации, totals, facets, границы московских суток и ACL; legacy array API сохранён.
- Backend typecheck — PASS; scoped ESLint по 7 затронутым файлам audit/history — PASS.
- Frontend typecheck с кэшем `/private/tmp/service-ops-crm-frontend.tsbuildinfo` — PASS. Первый запуск с кэшем в checkout получил EPERM; это не ошибка типов, повтор с доступным путём завершился успешно.
