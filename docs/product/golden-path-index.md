# Golden Path Index

## Объекты

- GP-OBJ-001: создание объекта руководящим кругом
- GP-OBJ-002: управление responsibles/managers/staffing
- GP-OBJ-003: ежедневный объектный цикл — arrival, report, attendance, feed
- GP-OBJ-004: изменение объекта через approval

## Задачи

- GP-TASK-001: создание задачи по объекту
- GP-TASK-002: закрытие задачи через подтверждение

## Табель

- GP-TS-001: attendance -> automatic day value
- GP-TS-002: ручная корректировка с причиной
- GP-TS-003: экспорт месячного табеля в Excel
- GP-TS-004: сводный табель по доступным объектам с Аванс / ЗП / Итого

## Разовые заказы

- GP-OTO-001: создание карточки заказа
- GP-OTO-002: работа по заказу с участниками, расходниками, файлами и задачами
- GP-OTO-003: отдельный табель разового заказа
- GP-OTO-004: поступление за заказ в подотчёт ответственного получателя и фактическая выплата уборщице отдельным расходом с раздельным отчётом «начислено / выплачено / ожидает проверки»

## Inventory

- GP-INV-001: обычное движение расходников
- GP-INV-002: исключение списания на объект без фото через director-only approval bridge

## Equipment

- GP-EQP-001: выдача/возврат/перемещение оборудования

## Employees-HR

- GP-HR-001: создание employee-карточки
- GP-HR-002: подмена по правилу процесса

## Expenses / accountability

- GP-EXP-001: выдача подотчета
- GP-EXP-002: фиксация расхода
- GP-EXP-003: отправка подотчета на сверку и закрытие

## Approvals

- GP-APR-001: создание объекта через правило “внес один — подтвердил другой”
- GP-APR-002: закрытие задачи через approval
- GP-APR-003: изменение объекта и assignments через approval

## Chats

- GP-CHAT-001: профильный чат с unread/read receipts
- GP-CHAT-002: редактирование собственного сообщения в ограниченное окно

## Notifications

- GP-NOT-001: события по задачам
- GP-NOT-002: события по approvals
- GP-NOT-003: события по чатам

## Candidates

- GP-CAND-001: создание кандидата и назначение менеджера
- GP-CAND-002: ответ менеджера в SLA или одно overdue-уведомление
- GP-CAND-003: кандидат резерва в HR-разделе без создания Employee

## Дополнительные согласованные процессы (2026-10-07)

- GP-CAL-001: безопасный доступ к своему/чужому календарю по роли и scope; API не доверяет входному `managerUserId`
- GP-CAL-002: персональный полный доступ Киреевой к календарям всех Users; остальные могут менять только свой календарь
- GP-OBJ-005: создание объекта, затем прикрепление файлов в «Материалы об объекте» и просмотр постоянных инструкций
- GP-CP-001: мастер-объект контрагента показывает дочерние объекты и их расходные операции без отдельного склада
- GP-OTO-004: planned vs actual attendance уборщиц, исправления с причиной и журналом, отчет по заказу/сотруднику/периоду
- GP-OTO-005: отзыв доступен любому пользователю, который может открыть соответствующий заказ
- GP-EXP-004: свободный внешний приход пользователя на собственный счет немедленно отражается в ledger и затем сверяется
- GP-OBJ-006: отдельные редактируемые сезонные профили лето/зима без пересчета исторических сумм
- GP-OBJ-007: управление ставками объекта и вариантами оплаты командой; deputy_director имеет только узкое право тарифов, а дополнительный выход менеджера ограничен назначенным объектом и аудируется
- GP-CARPET-001: количество ковров по размеру на объекте, стоимость замены и история изменений без индивидуальных номеров; проверяется `rubber-mats.integration.test.ts`

- GP-CAND-ACCESS-002: менеджер переключается между «Мои» и «Все», не получая чужого SLA-ответа; персональный запрет блокирует весь сценарий и поиск/уведомления
- GP-OBJ-CONTACT-001: контакты объекта с несколькими телефонами/почтами/ссылками; объектный scope, версии и аудит
- GP-OBJ-BUDGET-001: месячный расход по подтверждённым snapshot-движениям, возвраты и однократная доставка события роста перерасхода руководству
- GP-OBJ-SEASON-002: ежегодная граница сезона по Москве, независимый базовый профиль, ручной режим и сохранность исторических начислений
- GP-SUB-001: временное объектное замещение действует как union собственных и делегированных прав в выбранном scope
- GP-TS-005: выход при зарплатной модели формирует дневной факт табеля без дублирования; экспорт берет текущего менеджера
- GP-TS-006: сводная Excel-выгрузка утверждается только по предоставленному заказчиком образцу

- GP-OPS-ATT-001: предложение состава не создаёт факт; пустое подтверждение, доступность, автор/время и ставка подмены сохраняются (`object-operations-customer-changes.integration.test.ts`).
- GP-OPS-REPORT-001: черновик не публикуется, финальная отправка/обновление имеют независимые ревизии и повтор доставки не дублирует сообщение (тот же тест).
- GP-INV-CORRECT-001: scope, отмена неподтверждённой выдачи и один компенсирующий возврат при конкурирующих запросах (`inventory-corrections.integration.test.ts`).
- GP-MEDIA-BATCH-001: более десяти фото, retry без дубля, общее подтверждение движения и граница московского дня (`media-batch-retry.integration.test.ts`).
- GP-PLAN-001: персональные планы/сопровождающие, версии/история, сроки без догадок, разнесение услуг без изменения платежей (`plans-orders-operations.integration.test.ts`).
- GP-CHAT-PERSONAL-001: управление участниками не открывает администрирование/чужие комнаты; операционный менеджер не получает objects-сообщения (`chat-membership-access.integration.test.ts`).
- GP-NOTIFY-DISMISS-001: прочитанное скрывается только получателю, непрочитанное не скрывается, общий event не удаляется (`notifications-personal.integration.test.ts`).
