# Локальная сверка roadmap — 2026-10-26

Основная спецификация: `docs/product/customer-changes-2026-10-20.md`. Этот отчёт не подтверждает выкладку на сервер или визуальную приёмку.

## Реализация и проверенные ограничения

- Операционные фотографии: загрузка создателем — назначенным менеджером в день создания по Москве; после 23:59 только чтение. Фото может закрыть запрос согласования отсутствующего подтверждения. Одна общая фотография достаточна.
- Массовые файлы: галерея/выбор файлов допускают множественный выбор без ограничения в 10 штук. API сохраняет предел 25 МБ на один файл. Массовая загрузка отчётов и создания задачи ограничена тремя параллельными запросами; результат выполнения задачи загружается последовательно. Идентификатор загрузки защищает повтор от дублирования. Черновик и успешные файлы сохраняются при частичной ошибке.
- Посещаемость: предлагается последний сохранённый состав с проверкой доступности, но факт не создаётся до явного сохранения; пустое подтверждение также сохраняется. API возвращает имя сотрудника, автора и время отметки.
- Подмена: назначенный менеджер выбирает существующую объектную ставку; снимок не меняется после редактирования каталога, одновременные конфликтующие назначения не проходят.
- Коррекция расходников: неподтверждённая выдача отменяется; подтверждённая исправляется ровно одним обратным движением по исходной стоимости. Причина, актор, время и ссылка на возврат сохранены в транзакционном аудите. Исходное подтверждённое движение не удаляется и не переписывается.
- Ковры: ограниченный каталог размеров, количество на объекте, точный decimal-расчёт, версии/история. Миграция сохраняет старые карточки и события, неизвестную цену не подменяет нулём. Старые мутации отключены явно (410).
- Заказ: склад/оборудование показаны в отчёте в доступном scope; уборка и химчистка задаются явно и сверяются с итогом. Выплата сотруднику допускается без фото/чека, сохраняя получателя, сумму и независимое согласование.
- Планы: персональные права Лебедева/Горбачевой, собственный просмотр менеджера, чтение руководства, версии, внеплановые визиты, отчёт, история. Сопровождающие Дроздовского/Берендякова — отдельные непустые списки на заказ/дату. Просрочки формируются только при явном сроке, прекращаются после закрытия и дедуплицируются.
- Права: приватные причины календаря не раскрываются коллегам; HR-чтение отчётов/истории не выдаёт финансовые и операционные права. Персональное управление составом чата не открывает чужие комнаты. Операционный менеджер исключён из objects-чата, прямых API и realtime-получателей.
- UX: использованы существующие foundation/DatePicker/Select/Drawer/overlays/медиа-компоненты и --ui-*; очищены устаревшие классы, новых цветовых токенов и библиотек компонентов не добавлено.

## Что не закрыто

1. OQ-144: требуются смысл договорных сумм (начисление/выплата/оба), момент влияния на наличные, числовой пример и правила частичной выплаты/возврата. Договорное разнесение ГПХ/трудового договора и новая формула наличного остатка не внедрены на догадке. Существующие исторические расчёты сохраняются.
2. Текущая визуальная и интерактивная desktop/mobile-приёмка не выполнена: доступ инструмента к localhost ранее отклонён политикой браузера. Этот запрет не обходится другим браузером/каналом. Успешная сборка и API-тесты не заменяют скриншоты, клавиатурную навигацию, фактический drag-and-drop и оценку удобства.
3. Выложить на production можно только отдельным согласованным действием после приёмки; текущая работа ограничена локальной средой.
